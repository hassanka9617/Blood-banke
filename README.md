# تطبيق مخزون مصرف الدم (Android)

تطبيق أندرويد يعمل دون إنترنت لإدارة مخزون مصرف الدم بنظام الخفارات:
استلام الخفارة وجرد الرصيد، الإضافات، الصرف (دون السماح برصيد سالب)، التسويات الموثقة، الرصيد الحالي،
إنهاء الخفارة وترحيل الرصيد للخفارة التالية، وتقرير PDF عربي على ورق A4.

> التطبيق لحساب المخزون والتوثيق فقط، ولا يحل محل إجراءات التوافق أو القرارات الطبية المعتمدة.

## المعادلة

لكل صنف ولكل فصيلة بشكل مستقل:

```
الرصيد النهائي = الرصيد الافتتاحي + مجموع الإضافات − مجموع المصروفات (± التسويات المعتمدة)
```

## تشغيل المشروع خطوة بخطوة (للمبتدئ)

1. ثبّت **Android Studio** (مجاني) من الموقع الرسمي: https://developer.android.com/studio
2. فك ضغط ملف `BloodBankInventory.zip` في مجلد مثل `Documents/BloodBankInventory`.
3. افتح Android Studio ← **Open** ← اختر مجلد `BloodBankInventory` (المجلد الذي فيه `settings.gradle.kts`).
4. انتظر حتى ينتهي **Gradle Sync** في الأسفل (أول مرة قد تستغرق 5–15 دقيقة لأنه يحمّل المكتبات من الإنترنت).
   إذا ظهر اقتراح لتحديث Android Gradle Plugin يمكنك تجاهله الآن.
5. لتجربة التطبيق على هاتفك:
   - فعّل **خيارات المطور** في الهاتف (اضغط 7 مرات على "رقم الإصدار" في حول الهاتف) ثم فعّل **USB debugging**.
   - وصّل الهاتف بالحاسوب واضغط زر ▶ **Run** الأخضر في Android Studio.
6. لإنشاء ملف APK للتثبيت:
   **Build ← Build App Bundle(s) / APK(s) ← Build APK(s)**، ثم اضغط **locate** في الإشعار.
   الملف يكون في: `app/build/outputs/apk/debug/app-debug.apk`.
   انقله إلى الهاتف وافتحه (اسمح بتثبيت التطبيقات من مصادر غير معروفة).

### تشغيل اختبارات الحسابات

في Android Studio افتح الملف `app/src/test/java/com/bloodbank/inventory/domain/BalanceCalculatorTest.kt`
واضغط ▶ بجانب اسم الصنف، أو من الطرفية:

```
./gradlew testDebugUnitTest
```

### بناء APK تلقائياً على GitHub (اختياري)

المشروع يحتوي على `.github/workflows/build-apk.yml`. إذا رفعت المشروع إلى مستودع GitHub،
سيُبنى APK تلقائياً مع كل تعديل، وتجده في تبويب **Actions** ← آخر تشغيل ← **Artifacts**.

## أين كل شيء في الكود

| الملف | ماذا يفعل |
|---|---|
| `domain/BalanceCalculator.kt` | كل الحسابات (المعادلة، منع الرصيد السالب، الترحيل، الفروقات) |
| `domain/Models.kt` | الأصناف الأربعة وتصنيفاتها الافتراضية وأنواع الحركات |
| `data/Entities.kt` | جداول قاعدة البيانات (الخفارات، الرصيد الافتتاحي، الحركات، الرصيد الختامي، سجل التدقيق) |
| `data/InventoryRepository.kt` | منطق العمليات: الاستلام، الإضافة، الصرف، الإلغاء الموثق، إنهاء الخفارة |
| `pdf/ReportPdfGenerator.kt` | إنشاء تقرير PDF عربي A4 |
| `pdf/PdfActions.kt` | حفظ وطباعة ومشاركة PDF |
| `backup/BackupManager.kt` | النسخ الاحتياطي والاستعادة |
| `ui/screens/*` | الشاشات العربية |

## ضمانات مهمة في التصميم

- **الرصيد الافتتاحي ثابت**: يُحفظ جرد الاستلام في جدول مستقل ولا تغيّره الحركات اللاحقة.
- **منع الصرف الزائد**: يُعاد حساب الرصيد من قاعدة البيانات داخل معاملة واحدة قبل كل صرف.
- **منع التكرار**: لكل عملية حفظ معرّف فريد، فالضغط المزدوج على زر الحفظ لا يسجل الحركة مرتين.
- **منع الترحيل المزدوج**: لا يمكن أن تُرحَّل خفارة واحدة إلى خفارتين (قيد فريد في قاعدة البيانات)، ولا يمكن فتح خفارة جديدة قبل إغلاق الحالية.
- **لا حذف للبيانات**: الحركة الخاطئة تُلغى بعلامة "ملغاة" مع سبب، وتبقى في السجل والتقرير. الخفارة المغلقة لا تُعدَّل؛ أي تصحيح لاحق يكون بتسوية موثقة في الخفارة الحالية.
- **سجل تدقيق** لكل استلام، تسوية، إلغاء، إنهاء خفارة، تعديل إعدادات، ونسخ احتياطي.
- **التقرير = الشاشة**: التقرير يُبنى من لقطة الأرصدة المحفوظة لحظة الاعتماد، وهي نفس أرقام شاشة الإنهاء.
